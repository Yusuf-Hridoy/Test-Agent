### Defects found by live running (all fixed, all with regression tests)

1. `gemini-2.5-flash` retired for new keys — S0 could not run at all.
2. Login verdict raced the login form's own navigation → false AUTH_REQUIRED.
3. Login failure message matched saucedemo's own list of valid usernames (`error_user`).
4. "High demand" / transient 5xx not recognised as retryable by the failover classifier.
5. `gemini-3.6-flash` free tier is 20 requests/day — unusable for an agent session.
6. Redacting serialized JSON truncated strings containing `token=`, corrupting `session.json`.
7. Third-party hosts (saucedemo's analytics vendor) reported as application defects.
8. The same defect filed once per occurrence instead of once with a count.
9. A clean run's report showed no screenshots at all.
10. Click timeouts misclassified as site outages, burning 30/60/120s recovery cycles.
11. No per-request timeout on provider calls — a hung request could outlive `max_minutes`.
12. Repeated `look` calls invisible to the loop detector.
13. Re-rendered elements lost their snapshot tag (React), causing 15s click timeouts.
14. Findings carried the whole objective as repro instead of the steps that mattered.
15. **Credentials reached the terminal summary and HTML report** — only the on-disk JSON was redacted.
16. Filling form fields read as "no progress" — the fingerprint ignored input values, so the harness force-blocked legitimate form work.
17. **The planner silently dropped an impossible charter requirement**, producing a green report for work nobody did.
